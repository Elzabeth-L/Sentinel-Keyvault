Why this architecture

Security first, but still deployable

Public edge is controlled

  • Users enter through Azure Front Door.
  • WAF policy protects public routes.
  • Application Gateway is the regional ingress layer.

Data plane is private

  • Key Vault, ACR, Storage, and PostgreSQL use private endpoints.
  • AKS talks to private services through VNet DNS.
  • Public data access is disabled by default.

Identity replaces passwords

  • Workloads use managed identities.
  • Kubernetes service accounts use federated credentials.
  • RBAC is scoped per workload and resource.

AKS workload model

Microservices run with isolated identities and predictable rollout steps

Runtime shape

  • Web and API services are deployed as Kubernetes Deployments.
  • Inventory worker and outbox relay run separately in the workers namespace.
  • Database migrations run as a Kubernetes Job before application rollout.
  • Gateway service is an internal load balancer at the App Gateway backend.

Operational checks

  • Healthy: App Gateway backend health probe returns 200.
  • Healthy: Identity live and ready checks pass.
  • Healthy: Pods pull images from private ACR.
  • Watch: HTTPS custom domain depends on DNS validation.

Terraform structure

Environment folders instead of CLI workspaces

terraform/ bootstrap/ dev/ prod/ environments/ dev/ prod/ modules/ network/ monitoring/ data-platform/ aks/ application-gateway/ front-door/ workload-federation/

Why folder-based roots?

  • Dev and prod use different subscriptions and backends.
  • Production has Front Door; development does not.
  • RBAC, state, region, scale, and lifecycle rules are visibly different.
  • It is harder to accidentally deploy prod using a dev workspace selection.
